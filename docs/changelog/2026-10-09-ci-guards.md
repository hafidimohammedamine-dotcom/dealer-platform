# 2026-10-09 - CI guards and review policy

- **Guards** (`guards.yml`, `pull_request_target`, always runs `main`'s copy and scripts; the PR is data only):
  - Founder-only files may change only if the PR author **and** the account that pushed are in `.github/founders.txt`
    (`scripts/check-founder-files.sh`, 29 tests).
  - Skills must be in `.claude/skills/manifest.txt` and match `checksums.sha256`; third-party skills need NOTICE.md and a
    SKILLS-LOCK.md row (`scripts/check-skills.sh`, 25 tests).
  - Secret scan of the PR's commits with `main`'s config, ignoring `.gitleaksignore` and inline `gitleaks:allow`. The allow-list
    matches only AWS's documented example key, exactly (`scripts/gitleaks-config.test.sh`, 7 tests).
- **Review team** (`review.yml`, `pull_request_target`; the old `agent-review.yml` is deleted):
  - Rules, agents and skills come from `main`; the PR is prepared as data in `/tmp/pr` with rule files removed
    (`scripts/check-review-prepare.sh`, 8 tests) and is never run.
  - Waits for CI and guards, found by workflow file and event, not by check name (`scripts/check-pr-ci-status.sh`, 10 tests).
  - Claude only reads (tool allow-list, no web, no edits, no posting). A fixed step scans its answer for secrets, posts it and
    sets labels (`scripts/check-review-post.sh`, 12 tests). Job token only.
- **Daily report and weekly audit**: read-only allow-lists; their answer is posted by the same fixed step. The weekly audit no
  longer opens issues itself; the manager files them from the audit comment.
- **Manager**: tool allow-list instead of `bypassPermissions`; builder worktrees in `.worktrees/` (git-ignored) instead of `..`;
  manual runs only by a founder.
- **@claude mentions**: founder comments only; read-only answers.
- **CI** (`ci.yml`): runs the guard-script tests, scans all history on pushes to `main`, and runs install, lint, typecheck, test,
  build and dependency audit **when `package.json` exists** (skipped until the monorepo lands). No secrets.
- gitleaks is installed by one shared action (`.github/actions/install-gitleaks`), pinned by sha256. All actions pinned to commit SHAs.
- Agent jobs print their blocked tool calls (tool and command only) after each run, to tune the allow-lists.
- Removed `id-token: write` from the review, report, audit and manager jobs (kept only where the @claude action needs it), and
  `show_full_output` from the manager and review jobs.
- **Review policy** for third-party skills in CLAUDE.md (five risk types; examples breaking key rules are always findings).
- **Ownership:** `.github/`, guard scripts, `.gitleaks.toml`, `.gitleaksignore` are founders-only; devops proposes CI changes with `REQUEST:`.
- **Accounts:** agents push with their own GitHub account (`AGENT_GH_TOKEN_V2`, account `mohammedaminehafidi-ctrl`), never a
  founder's token.
- CODEOWNERS added. Runbook: `docs/runbooks/ci-guards.md`. Architecture: `docs/architecture.md`.
