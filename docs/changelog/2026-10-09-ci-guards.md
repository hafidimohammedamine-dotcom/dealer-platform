# 2026-10-09 - CI guards and review policy

- **New `guards` workflow** (`pull_request_target`, always runs `main`'s copy and scripts; the PR is data only):
  - Founder-only files may change only in PRs opened by an account in `.github/founders.txt` (`scripts/check-founder-files.sh`, 26 tests).
  - Skills must be in `.claude/skills/manifest.txt` and match `checksums.sha256`; third-party skills need NOTICE.md and a
    SKILLS-LOCK.md row (`scripts/check-skills.sh`, 25 tests).
  - Secret scan of the PR's commits with `main`'s `.gitleaks.toml`, ignoring `.gitleaksignore` and inline `gitleaks:allow`.
    The allow-list matches only AWS's documented example key, exactly (`scripts/gitleaks-config.test.sh`, 7 tests).
- **New base-defined review** (`review.yml`, `pull_request_target`): rules, agents and skills come from `main`; the PR is read
  from `/tmp/pr` with its rule files removed and is never run; waits for CI; tool allow-list, no web access, no file edits;
  uses the job's own token (comment and label only). The old `agent-review.yml` stays for this PR only.
- **CI** (`ci.yml`) runs tests, lint, typecheck, build and the guard-script tests; no secrets. gitleaks pinned by sha256; `yarn build` added.
- **All GitHub Actions pinned** to full commit SHAs.
- **Daily report and weekly audit** use the job token and a tool allow-list instead of `bypassPermissions`.
- Removed `id-token: write` from the review, report, audit and manager jobs, and `show_full_output` from the manager and review jobs.
- **Review policy** for third-party skills (five risk types; example code breaking key rules is always a finding) in CLAUDE.md.
- **Ownership:** `.github/`, guard scripts, `.gitleaks.toml` and `.gitleaksignore` are founders-only; devops proposes CI changes with `REQUEST:`.
- **CODEOWNERS** added (enforced once branch protection requires code-owner review).
- Runbook: `docs/runbooks/ci-guards.md`.
