# 2026-10-09 - CI guards and review policy

- **Founder-only files** (any `CLAUDE.md`, `CLAUDE.local.md`, `.mcp.json`, `.claude/`, `.github/`, guard scripts, `.gitleaks.toml`,
  `packages/contracts/`) can only change on `founder/` branches. New CI check: `scripts/check-founder-files.sh` (16 tests).
- **Skills** in `.claude/skills/` must be listed in `manifest.txt` and match `checksums.sha256`. New CI check:
  `scripts/check-skills.sh` (21 tests). CI always runs the base branch's copy of both guard scripts.
- **Secret scan** uses a checksum-pinned gitleaks binary; `.gitleaks.toml` allows only AWS's documented fake example key
  (5 tests in `scripts/gitleaks-config.test.sh`).
- **All GitHub Actions pinned** to full commit SHAs. CI now also runs `yarn build`.
- **Review team** reads CLAUDE.md, `.claude/`, nested `CLAUDE.md`/`CLAUDE.local.md` and `.mcp.json` from the base branch, and uses the
  job's own GitHub token (comment and label only) instead of a founder token. Daily report and weekly audit use the job token too.
- **Review policy:** third-party skills are reviewed for five risk types (see CLAUDE.md "Review policy"); everything else keeps zero findings.
- **CODEOWNERS** added for founder-only paths (enforced once branch protection requires code-owner review).
- **Ownership:** `.github/` and `.gitleaks.toml` moved to the founders-only row; devops proposes CI changes with `REQUEST:`.
- Runbook: `docs/runbooks/ci-guards.md`.
